# Shared class contracts v1 — established before Warrior implementation

`Catalog.classes` is a validated browser-safe execution section, composed with the existing catalog. Its generated JSON is separate from Node-only locked-source compilation. Identity/description evidence never implies executable mechanics. All 56 source matrix combinations may be created; only a class with an explicit execution package may use class operations. Starting stats, ID mappings, default tactics, training transactions and unsourced timing are named owned Idle adaptations. Unsupported talents/racials remain source evidence and cannot be selected.

Persistent `CharacterState` owns level, class, talents, known ranks and class progress. `materializeCharacterActor(character)` creates an actor with a `classState` snapshot for the required actor-only `deriveActor(actor,catalog)` and `validateTalentAllocation(actor,allocation,catalog)` interfaces. The snapshot contains class, level, base stats, talents, known spells and stance. It is a derived cache, never an independent authority. Commands refresh it atomically when persistent state changes; GameState validation checks equality wherever both exist. Combat derives from persistent character state, never trusts cached talent values over it. Class operations fail closed without a snapshot. Legacy actors without class progress/snapshot keep T07 behavior.

Creation accepts identity input only and resolves the allowed matrix from the catalog. It is pure and does not activate a profile character. Training and specialization commands return new GameState only after all preconditions pass; rejected commands return no mutated state. Trainer location, class, level, previous rank, quest and reagents are explicit catalog requirements. Combat rank/form/reagent validation occurs before resource consumption. Class actions use existing simulation time, seeded RNG and ordered effect/event machinery.

Resource and form modules own pure derivation and transformations; no ambient clocks, random numbers, I/O or hidden timers. Talent allocation validates integer ranks, class ownership, source prerequisites, authored row gates and point budget. Offered effects must have executable consumers; unsupported source talents never consume points. Dual specialization stores two independent allocations, unlocks at the primary-source level and uses explicitly authored transaction/switch rules. Each offered profile supplies an executable tactic with attack fallback.

Pet contract is reserved: pets must become independent encounter actors with owner ID, health/resource/cooldowns/tactics/state, and consume zero party slots. Warrior has no pet support. Hunter/Warlock/Shaman packages must add concrete actor variants and update friend/enemy/death semantics together; a metadata-only pet is not an implementation. Later packages may extend these contracts explicitly with tests and a recorded contract revision; they may not silently reinterpret ownership, source status, clock/RNG or allocation semantics.

Optional aura `exclusiveGroup` replaces only another aura in that group from the same caster on the same target. Might and Wisdom share the Paladin blessing group; other casters and targets are unaffected, and obsolete periodic tokens do not execute. Buffs may add attack power and a Holy-only threat multiplier. ### Hunter review amendment — bounded hostile approach and exact pet ranks

A hostile melee NPC may approach a ranged Hunter using the existing attack action. Candidate selection includes approachable Hunters, so a pet's death cannot remove the owner's incoming pressure. The hash-locked, typed class rule `hunterApproachMs: 1000` is an owned Idle delay; the attack schedules one `melee-impact` with optional `closeDistance: true`, and its next attack clock includes both approach delay and normal swing interval. A second attack cannot queue another approach while that clock is pending. No general coordinates or free disengagement/kiting are introduced; other classes and legacy impacts retain their rules.

At contact, the handler checks living hostile melee NPC, living Hunter, opposing sides, owner/target zone, running encounter and supported class package before mutating formation. Dead, departed, friendly or invalid approachers never move the Hunter. Valid contact sets the Hunter's encounter position to melee, resolves the ordinary melee swing, and resumes both actors' legal future decisions. Shots work before contact and fail ranged requirements afterward; Hunter's normal melee attack fallback then continues. Two enemies already approaching may both swing once the first has established melee contact. Serialized/sliced execution retains the same transition and incoming damage.

Pet known ranks must match the complete authored spell set with equal cardinality and no duplicates. Removed Growl, added owner spells and duplicated Growl all fail before action/effect mutation; queued impacts roll back rather than execute with an incomplete pet.
