`registry.json` describes source roles and limits. `lock.json` repeats that registry and records each exact captured file: repository commit and Git blob where applicable, SHA-256, byte length, original path, repository-local evidence path, branches, supported fields, languages, build and limitations. Unknown builds are `null`. A pinned repository with no captured file is explicitly `pinned-unretrieved`.

GitHub bytes under `vendor/` were retrieved exclusively through the ChatGPT GitHub connector and copied without rewriting or decompression. The client extracts retain their original gzip bytes. No upstream code is executed by verification. The official article files under `evidence/` are small factual extractions from the web tool, not original HTML downloads; their hashes cover only the saved extraction. The first-raid names and date are from an official-domain search excerpt because the full raid overview was unavailable. Separate official articles support Barrow Deeps and Hyjal Summit sizes and boss counts. Onyxia's raid size remains unknown in the captured evidence.

`npm run test -- tests/content/source-lock.test.ts` parses the lock and verifies every captured file's SHA-256, byte length and Git blob hash where available. This is Node-only build tooling; source bytes and `node:crypto` are not imported by the game runtime.
